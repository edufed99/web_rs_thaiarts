# ADR-001: Refactor Thai Arts Recommender Web App

**Status:** Accepted
**Date:** 2026-07-28
**Scope:** Replace the Django-based `thai_arts_webapp` runtime architecture with a Next.js + FastAPI split, while preserving the recommendation algorithm unchanged.

---

## 1. Problem

The current system (Django 6 + PostgreSQL, located at `web_appRS/thai_arts_webapp/`) has the following structural problems that block production deployment:

1. **Runtime coupling to heavy ML models.** `recommender/cbf.py` lazily loads `intfloat/multilingual-e5-large-instruct` via `sentence-transformers` on every cold start. Although `get_sentence_transformer` is `lru_cache(maxsize=1)`, the model still occupies ~2 GB of process memory for every web worker. There is no prebuilt artifact.
2. **Database roundtrip on every request.** Item embeddings, item-keyword links, contexts, user history (ratings, likes, saves, legacy logs), and recommendation requests are all fetched live from PostgreSQL on each `/api/recommendations/` call. A request can fan out into 50+ DB queries before ranking.
3. **No separation between training-time and serving-time concerns.** `manage.py build_item_embeddings` mutates the DB inside an HTTP worker context. There is no clear "artifact" boundary.
4. **Tight coupling to Django ORM in business logic.** `services.py`, `cbf.py`, `cf_itemknn.py` all import Django models (`Item`, `Keyword`, `Rating`, `Like`, …). This makes it impossible to reuse the algorithm outside the Django process — e.g. from a Jupyter notebook, a CLI script, or a separate API tier.
5. **Frontend is server-rendered Django templates**, not a decoupled SPA. This is fine for the prototype but blocks any non-browser client (mobile, embed, CLI) from consuming recommendations.
6. **No Swagger / OpenAPI surface.** API endpoints are documented only by reading `recommender/api.py` and `config/api.py`. There is no machine-readable contract.

The deliverable of this refactor is a **new** project at `web_appRS1/` (root) that preserves the existing algorithm but moves all runtime data through **prebuilt artifacts** and exposes the system through a clean FastAPI + Next.js boundary. The legacy Django project at `web_appRS/thai_arts_webapp/` is **not modified** — it remains as the reference implementation.

## 5. API Design

### `GET /health`

Liveness probe. Returns 200 with build metadata.

```json
{
  "status": "ok",
  "artifacts_loaded_at": "2026-07-28T14:00:00Z",
  "item_count": 114,
  "version": "1.0.0"
}
```

### `POST /recommendations`

**Request:**
```json
{
  "context_id": 1,
  "keyword_ids": [12, 47, 103],
  "top_k": 10
}
```

**Response 200:**
```json
{
  "request_id": "uuid",
  "selected_context": { "id": 1, "name": "งานบวช", "group": "พิธีกรรม" },
  "selected_keywords": [{ "id": 12, "name": "ผู้ชาย" }],
  "candidate_count": 42,
  "top_k": 10,
  "results": [
    {
      "rank": 1,
      "item": { "id": 7, "name": "ระบำพรหมาสตร์", "category_group": "ระบำ", "...": "..." },
      "scores": { "cbf": 0.84, "cf": 0.51, "hybrid": 1.23 },
      "is_context_valid": true,
      "matched_keywords": ["ผู้ชาย"],
      "explanation": "รายการนี้ผ่านเงื่อนไขบริบท \"งานบวช\" …"
    }
  ]
}
```

**Errors:** `400` invalid input, `404` context not found, `503` artifact not loaded.

### `GET /items`

Returns paginated list of active items (id, name, category, performance_type, image_url). Defaults to first 20.

### `GET /items/{item_id}`

Returns one item with attached `keywords`, `contexts`, `matched_user_state`.

### `GET /contexts`

Returns all filterable subcontexts (id, name, group, description, active_item_count).

### `GET /keywords`

Returns all keywords with optional `?context_id=` filter and `?search=` prefix.

### `GET /metrics`

Returns aggregated counts: items, contexts, keywords, candidates per context, artifact build timestamp.

## 6. Model Artifact Strategy

Artifacts are split into two subdirectories by **role**:

### `artifacts/models/` — ML model artifacts (input สำหรับ serving)

| Artifact | Format | Producer | Consumer | Contents |
|----------|--------|----------|----------|----------|
| `item_embeddings.npz` | NumPy npz (float32) | pipeline | backend | Precomputed E5 vectors for every active item. Replaces `ItemEmbedding` table. |
| `item_embedding_ids.json` | JSON array of ints | pipeline | backend | Parallel array of item ids for the embedding matrix. |
| `cf_user_item.json` | JSON `{user_key: [item_ids]}` | pipeline | backend | Positive interaction history (legacy rating ≥4, Rating ≥4, Like). Replaces `LegacyInteraction + Rating + Like` query. |
| `cf_item_users.json` | JSON `{item_id: [user_keys]}` | pipeline | backend | Inverse index for cosine sim. Built once from `cf_user_item.json`. |
| `cf_user_item_rating.json` | JSON `{[user,item]: weight}` | pipeline | backend | Rating weight per pair (for cosine weighting). |

### `artifacts/outputs/` — Processed data ที่ derive จาก source CSV

| Artifact | Format | Producer | Consumer | Contents |
|----------|--------|----------|----------|----------|
| `catalog.parquet` | Apache Parquet | pipeline | backend | Item rows joined with Context, Keyword, TaxonomyNode via embedded lists. Replaces all ORM queries. |
| `metadata.json` | JSON | pipeline | backend | Build timestamp, item count, config hash, schema version. |

### Loader convention

`ArtifactLoader` reads from both subdirs at startup:
- `models_dir = <artifact_root>/models`
- `outputs_dir = <artifact_root>/outputs`

Both are configurable via env (`RECSYS_ARTIFACTS_MODELS_DIR`, `RECSYS_ARTIFACTS_OUTPUTS_DIR`) or via a single `RECSYS_ARTIFACT_DIR` (defaults to `<artifact_root>` with `models/` and `outputs/` subdirs).

**Pipeline entry point:** `pipelines/train_or_generate_artifacts.py`

**Invocation:**
```bash
python pipelines/train_or_generate_artifacts.py \
    --source-root web_appRS/source_data_2569/code\ for\ paper/4.recommendation/input \
    --output-dir web_appRS1/artifacts
```

**Re-run triggers:** source CSVs change, new E5 model, new seed for sampling. Not a runtime concern.

**Backend loading:** `model_loader.ArtifactLoader` is instantiated in FastAPI `lifespan`. If any required artifact is missing, the loader raises `ArtifactsNotLoadedError`, the lifespan returns 503 from `/health`, and the FastAPI app refuses to mount recommendation routes.

## 7. Swagger / OpenAPI Strategy

- FastAPI auto-generates OpenAPI 3.1 schema at `/openapi.json`.
- Swagger UI at `/docs` (FastAPI default).
- ReDoc at `/redoc` (FastAPI default).
- All endpoints carry `summary` (one line) and `description` (paragraph + examples).
- All request/response models are Pydantic v2 with `Field(description=...)` so schema carries field-level docs.
- A separate `docs/api.md` provides a human walkthrough and example curls.

## 8. Testing Strategy

**Tooling:** `pytest`, `pytest-cov`, `pytest-asyncio`, `httpx` (for `AsyncClient`).

**Coverage target:** ≥ 90% for `backend/app/` (excluding `__init__.py`).

**Threshold enforcement:** `pytest.ini` runs with `--cov=app --cov-report=term-missing --cov-fail-under=90`.

**Test layout:**
```
backend/tests/
├── conftest.py              ← fixtures: sample artifacts in tmp_path, FastAPI TestClient
├── test_health.py           ← GET /health returns 200 with expected shape
├── test_recommendations.py  ← happy path + invalid top_k + missing context + missing artifact
├── test_catalog.py          ← list, detail, 404
├── test_metrics.py          ← shape, item count
├── test_eligibility.py      ← service-level: context filter, keyword-hit prioritization
├── test_cbf_service.py      ← cosine on precomputed vectors, keyword boost
├── test_cf_service.py       ← ItemKNN scoring, popularity fallback
├── test_hybrid_service.py   ← z-score calibration, weighted sum
├── test_model_loader.py     ← load OK, missing file, partial load, schema mismatch
└── test_explanations.py     ← matched/unmatched keyword branches, taxonomy summary
```

**Artifact fixtures:** `conftest.py` writes a 5-item / 2-context / 3-user synthetic parquet + json into a tmp dir before each test, so tests are deterministic and need no source CSVs.

## 10. Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| **Algorithm drift.** Porting 4 services from Django ORM to artifact-loaded pure Python risks subtle behaviour change. | Keep the ports as 1:1 as possible. Add a "sanity check" test that runs the new pipeline against the legacy DB and asserts identical top-3 for a seeded context. (Post-M3.) |
| **Artifact staleness.** If source CSVs change, recommendations go stale silently. | `metadata.json` carries `build_timestamp` and `config_hash`; `/health` exposes them; `README.md` documents how to re-run the pipeline. |
| **Cold start latency.** Loading `artifacts.parquet` + npz on first request is slower than DB. | Use FastAPI `lifespan` to load once at startup, not per-request. Target < 2 s for 1k items. |
| **Sentence-transformers still needed at pipeline time** to embed new items. | Pipeline is offline; no serving-time impact. Document `pip install sentence-transformers` as a pipeline-only dep. |
| **No user personalization at runtime** in this MVP (the legacy `personalized_recommendations_from_history` is deferred). | Out of scope. Documented in §11. CF index still uses historical ratings as a static artifact, so "popularity fallback" still works. |
| **Language mismatch on negative penalty.** Legacy `apply_negative_penalty` requires live user ratings per request. | Defer live personalization; static CF index assumes positive history only. Documented as M9 backlog. |
| **Two systems coexisting.** During transition both Django and FastAPI may run on different ports. | Use ports 8080 (backend) and 3000 (frontend). Django stays at 8000. Document in README. |
| **Coverage threshold may be brittle** as new code lands. | Pre-commit hook (out of scope here) could enforce; for now, CI is manual `pytest` run. |

## 11. Out of Scope

The following are explicitly **not** part of this refactor:

1. **Authentication / login / consent flow.** Legacy `accounts/` is left untouched. Backend endpoints are open in this MVP. Production must add OAuth or JWT — separate ADR.
2. **Live user personalization** (`personalized_recommendations_from_history`, like / save / rate actions). CF uses static historical-positive index only. No `InteractionLog` writes at runtime.
3. **Migration of existing PostgreSQL data.** The Django DB stays where it is; the new system reads CSVs and rebuilds artifacts from scratch.
4. **CI/CD, Docker, deployment scripts.** Manual `uvicorn` and `npm run dev` only.
5. **Replacing `intfloat/multilingual-e5-large-instruct` with a smaller model.** Pipeline uses the same model the legacy system uses.
6. **Cloud storage, cloud database.** Artifacts are local files.
7. **i18n / localization of API responses.** Backend uses Thai names directly from the catalog CSV.
8. **Modifying or moving the legacy Django project.** It lives at `web_appRS/thai_arts_webapp/` and remains the reference implementation.

## 12. Acceptance Criteria

The refactor is considered complete when:

1. `pipelines/train_or_generate_artifacts.py` runs end-to-end against `web_appRS/source_data_2569/code for paper/4.recommendation/input/` and writes 7 artifacts.
2. `backend/` boots with `uvicorn app.main:app --reload`, exposes `/health`, `/recommendations`, `/items`, `/items/{id}`, `/contexts`, `/keywords`, `/metrics`, `/docs`, `/openapi.json`, `/redoc`.
3. `pytest --cov=app --cov-report=term-missing --cov-fail-under=90` exits 0 with ≥ 90% coverage.
4. `frontend/` runs with `npm run dev`; `/recommend` submits a recommendation request and renders the top-K results with explanations.
5. The legacy Django project at `web_appRS/thai_arts_webapp/` has zero modifications after the refactor (`git diff` clean against its own HEAD).
6. Frontend never imports a Python file, never reads CSV, never reads `artifacts/*` directly. Only HTTP to backend.
7. Backend never reads CSV at serving time. Only `artifacts/*` and static seed data inside the backend package.
8. Swagger UI renders at `/docs` with summary + description on every endpoint.
